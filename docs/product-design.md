# 小红书图文内容 Agent：MVP 设计
版本：0.2｜日期：2026-10-13｜阶段：设计，不包含代码实现或自动发布

## 1. 产品定义
输入创作意图、目标和可选素材，系统自行补充调研、提出内容角度、组织文案、选择素材、制作整组图文、检查问题，最终交付可审核、可修改、可下载的发布包。

默认用户为个人创作者，第一版面向小红书知识/工具/经验类图文。生活、美食、产品体验等依赖真实经历的内容，必须由用户提供经历或照片，系统不可编造亲身体验。抖音图文通过后续平台适配器扩展。

北极星指标：每篇“经用户审核可发布作品”的总耗时及人工修改量。阅读、收藏、关注属于发布后的结果指标，生成阶段不能保证。

核心差异：热点驱动与目标筛选、来源可追溯、真实经历约束、视觉一致性、局部编辑、人工反馈，而不是增加 Agent 数量。

## 2. 输入与目标
必填：意图（一段自然语言即可）。其他字段可从账号档案继承；首次创建时明确展示默认假设，只针对影响方向的缺口追问，最多 2 个问题。
- primary_goal：收藏 / 关注 / 评论 / 点击；MVP 一篇只选一个主目标。
- audience：目标读者、已知基础、痛点。
- account_profile：账号定位、口吻、视觉偏好、已有内容。
- user_materials：链接、照片、截图、文档、本人经历。
- content_type：知识清单 / 工具教程 / 有依据的观点比较。
- constraints：页数、生成预算、时效性、禁用说法、是否允许 AI 配图。
- platform：MVP 为 xiaohongshu；未来 douyin。
- mode：默认热点参考生成；可选策划确认模式。

目标改变内容策略：
| 目标 | 内容策略 | 验证代理指标 | 发布后指标 |
|---|---|---|---|
| 收藏 | 清单、步骤、模板、可复用信息 | 具体行动数、可操作性、信息覆盖 | 收藏/阅读 |
| 关注 | 明确领域定位、系列延续价值 | 受众一致性、后续主题可延展性 | 可归因新增关注/阅读，若无法归因则记录原始数据 |
| 评论 | 有实质争议的问题、可回应的经验征集 | 问题明确性、观点依据 | 有效评论/阅读 |
| 点击 | 明确收益与下一步入口 | 链接与承诺一致性 | 平台允许且可统计的点击/阅读 |

不输出“爆款概率”“保证涨粉”；这些无法用生成内容直接验证。

## 3. 用户流程
快速模式：输入意图 → 展示解析和假设 → 热点采样、事实调研并选择最符合目标的角度 → 生成预览 → 用户修改/审核 → 下载。
策划模式：输入 → 3 个选题角度与证据摘要 → 用户选角度 → 生成预览 → 审核 → 下载。

生成结果：
- 3 个候选标题、1 个推荐标题，候选按承诺和语气区分。
- 1 篇正文和话题候选。
- 默认 6 张卡片：封面、问题/背景、3 张核心内容、总结/行动。
- 页面数量 4–9 为产品初始配置，不视为平台硬限制。
- 同组风格规范：字体、主色、背景、间距、装饰、角色或主体参考。
- 素材清单与事实来源。
- 可选 BGM 建议：情绪、节奏、关键词、候选曲目（仅经查询核实才列曲名）。
- AI 参与说明建议、发布前提示。
- 发布包：01-cover.png、02.png…、caption.md、sources.json、music.md、project.json。

不要将音乐嵌入 PNG。图片序列与音乐是不同交付物；平台内可用曲目在发布时由用户确认。图文不加音乐也能完成 MVP。

## 4. 调研分为两个通道
### 事实调研
针对产品能力、价格、操作方法、统计等事实优先查询原始文档、官方公告和可靠第一手材料。每项记录 URL、页面日期、访问日期、摘要、原文片段及其支持的 claim_id。

处理规则：
- 来源不足：继续检索、缩小结论、标记待核实或删除；禁止补造事实。
- 相互冲突：优先检查日期、版本、适用对象，不把较新自动等同于较可靠。
- 时间敏感内容：对版本/价格/可用性重新核实，并在正文说明适用日期。
- 用户经历是用户提供的信息，不自动视为普遍事实。
- 每个核心事实映射到证据；无需把每一句创作性文字都加引用。

### 平台内容观察
观察标题结构、封面信息量、常见读者问题、评论需求和同题材差异。优先用户提供参考链接、截图、评论，之后可选接入独立只读适配器。

搜索引擎结果不是全量小红书数据；不得虚构站内搜索、互动数、热门排名和热度趋势。若无站内数据，明确写“基于公开网页与给定样本”。

样本记录：查询词、获取时间、排序方式、样本数量、发布日期、公开互动数及缺失字段。少量高互动内容不能证明某种写法必然有效；避免只采爆款造成选择偏差。

第一版设置默认调研预算：最多 6 次搜索、读取 8 个页面、2 轮补充检索。均可配置。预算耗尽时返回证据缺口。

## 5. 素材策略
素材优先级是产品默认，可由作品类型覆盖：
1. 用户原创照片、真实操作截图、可授权素材。
2. 项目自行绘制的流程图、图标、数据图和模板。
3. 已确认授权范围的图库素材。
4. 用于解释或装饰的 AI 插画。

每条素材记录 source_url、creator、origin_type、rights_status、license_url、allowed_use、attribution、hash、generation_provenance。来源明确不等于可复用授权；未知授权素材保留为调研参考，暂不进入发布包。

功能演示必须用真实截图；AI 插图标注为示意，不生成虚假软件界面充当实测证据。人物/产品要求跨页一致时，复用已选参考图和同一 art_direction。

BGM：
- 首版必交付的是建议，不是音频下载。
- 未查到曲目时只给风格与搜索词。
- 若未来导出带音乐视频，需要单独记录平台、用途、地区、有效期和授权证据；平台曲库选择不推导为跨平台使用授权。
- 音频生成接口作为后续可插拔功能，不占首版关键路径。

## 6. 生成结构：正文与图片同源
先产出 ContentPlan，再生成正文和 SlideSpec。每页一个主要观点，正文作补充，不机械重复全部图片。

ContentPlan 包含：target_reader、primary_goal、angle、promise、claims、outline、cta、uncertainties。
SlideSpec 包含：slide_id、role、headline、body_blocks、claim_ids、asset_ids、layout_id、art_direction_id。
每页 body_blocks 使用结构化标题、段落、列表或对比字段；不让 LLM 输出任意可执行 HTML。

默认画布 1080×1440（3:4），这是设计默认值，不宣称平台强制要求。页数、比例、标题/正文长度及标签规则由 PlatformProfile 配置，发布前依据当前平台界面更新。

做图采用双模式：
- 知识卡片：代码模板排版文字，AI 只生成必要插图。先做 3 套模板：清单、步骤、对比。
- 视觉叙事：生成带参考的主视觉，再叠加可编辑文字。纯 AI 整页生成作为可选模式，必须核验文字。

推荐 HTML/CSS 模板 + Playwright 输出 PNG，插图经图片模型生成/编辑。字体用明确授权的字体。排版约束由程序检测：文字溢出、元素遮挡、边距、文件尺寸和分辨率。VLM 辅助检查读者视角的层次、一致性和图文匹配；不以 VLM 判断替代尺寸检测。OCR 用于整页 AI 图中文字核验。

修改规则：
- 改标题或正文：只重新排版受影响页面。
- 换插图：只替换该 asset_id 与引用它的页面。
- 改事实：修改 claim 与所有依赖该 claim 的文案/页面。
- 改选题或目标：重新策划，保留可复用证据和素材。
- 每次修改创建 revision，已审核版本不可静默覆盖。

## 7. Agent 架构
一个 LangGraph 图即可。角色是任务节点，不必部署为多个独立对话 Agent。
| 模块 | 职责 | 决策/动作 |
|---|---|---|
| Planner | 意图解析、目标和预算、选题 | 判断追问、检索范围、内容形式 |
| Researcher | 事实检索、样本观察、证据对齐 | 调用搜索/读取；发现缺口时补查 |
| Writer | 大纲、正文、标题、SlideSpec | 基于目标与证据改写 |
| ArtDirector | 素材选择、风格、配图规划 | 复用/搜图/生成；选择模板 |
| Reviewer | 程序检查与模型审稿 | 按错误类型回路到对应节点 |
| Renderer / Exporter | 模板渲染、打包 | 确定性代码，不承担事实判断 |

路由：信息缺口→追问；事实不足→补查；授权不明→替换素材；文字溢出→缩减文案或换模板；图文不符→改插图；审核通过→等待用户确认→导出。每个质检问题最多自动修复 2 次；仍不通过则保留可编辑结果与问题，不无限循环。

这体现了 Agent 的目标驱动、工具选择、状态保留和反馈修正。对于意图/素材已足够的任务，允许直接走短路径，避免为了“像 Agent”而强行搜索。

## 8. 状态与持久化
GraphState 的最小字段：
project_id、job_id、revision、status、brief、account_profile_ref、plan、
evidence_ids、claim_ids、asset_ids、slide_specs、draft、
issues、budget_used、approval、artifact_ids、trace_id。

数据库实体：
- accounts：账号档案及明确确认的偏好。
- projects / revisions：意图、内容计划、编辑历史。
- jobs / node_runs：运行状态、尝试次数、输入哈希、调用耗时。
- evidence / claims：证据与事实映射，支持多对多。
- assets：授权/出处/生成记录。
- slides / artifacts：页面结构与渲染输出。
- approvals：所审核 revision、审核时间、状态。
- metrics：用户录入的发布后数据与时间窗口。

图片和音频字节放文件/对象存储，不写入图状态。生产 checkpoint 放 PostgreSQL，单机实验可用 SQLite。
工作记忆保存一篇作品的过程；账号长期记忆只保存用户确认的偏好、采用/拒绝的样例，不把模型猜测自动固化。

## 9. 工程选型
建议：React + TypeScript 前端，FastAPI + LangGraph 后端，PostgreSQL，独立后台 worker，HTML/CSS + Playwright 图片渲染，可替换的文本/图片/搜索 provider。
首次单人本地试验可用 SQLite 和本地文件，架构稳定后迁移 PostgreSQL 与对象存储；不必先引入向量数据库或复杂多服务。

API：
- POST /projects：创建输入与默认假设。
- POST /projects/{id}/runs：启动 revision 的生成任务，带幂等键。
- GET /jobs/{id}/events：SSE 进度、检索摘要、页面完成事件。
- POST /jobs/{id}/cancel：明确取消。
- PATCH /projects/{id}/slides/{slide_id}：编辑结构化页面。
- POST /projects/{id}/slides/{slide_id}/regenerate：局部重生成。
- POST /projects/{id}/approve：审核指定 revision。
- POST /projects/{id}/export：导出指定 revision。

运行约束：
- SSE 断开只表示前端失联，后台生成任务仍可持续；用户点击取消才标记取消，停止新调用并尽量终止正在执行的调用。已发生费用可能无法撤回。
- 支持断线重连，事件带 event_id；用户重开作品可查看已完成页面。
- 重试只针对短暂服务错误；事实缺口走内容补查。429 使用退避，配图并发首版为 2。
- 对节点输出、素材和渲染按输入哈希缓存；按 job_id+revision+node+input_hash 管理幂等。checkpoint 不自动保证图片 API 只计费一次，需记录调用/结果并优先使用上游幂等键；结果不明的调用标记 uncertain。
- 预算包括模型调用次数、搜索次数、图片张数及累计成本。费用来自真实调用记录，不编造人民币报价。
- 外部网页是资料，不能改写系统指令；检索和素材下载限制协议、目标地址、大小和类型，避免内部地址请求；正文不能执行任意脚本。
- 模型密钥仅在后端。站内接入如需账号凭证，独立保管，不进入 prompt、日志或项目导出包。

## 10. 界面
三个主区域：
1. 输入/策划：意图、目标、材料、默认假设、3 个角度（策划模式）。
2. 创作工作台：左侧来源和过程，中间整组图文，右侧标题正文与逐页编辑。
3. 审核/导出：当前问题、来源可用性、AI 参与说明、音乐建议、下载。

优先操作：改标题、缩短这页、换图、锁定页面、调整顺序、重新生成选中页。大改前展示影响范围，锁定页面若依赖旧事实则提示冲突。

## 11. 一局真实任务示例
输入：“给没用过 AI Coding 的大学生讲清楚怎么开始，希望大家收藏，做 6 页，语气直接。”
解析：primary_goal=save；受众=大学生初学者；形式=步骤清单；不默认用户亲测过所有工具。
选题候选：工具比较 / 第一个小项目实操 / 常见踩坑；推荐“小项目实操”，因为可以形成可执行清单，此推荐是策略推断而非流量预测。
调研：读取所选工具当前官方使用文档，核实安装和必要条件；如无法证实费用，删除具体价格。
卡片：
1. 封面：第一次用 AI 写代码，从这个小项目开始。
2. 范围：做待办页面，只包含增删和本地保存。
3. 准备：编辑器、项目启动方式、工具必要条件。
4. 提问：目标、输入输出、验收条件、不要做的功能。
5. 验证：启动、添加、删除、刷新后持久化，展示真实截图或图示。
6. 收藏清单：先跑通→逐步改→手动验收；补充下一步。
图片：模板排版 + 用户截图/自制示意，不伪造软件截图。
音乐：可选轻量无歌词/低干扰节奏，发布时平台内搜索确认。
质检：检查操作来自当前文档、是否有无依据效率承诺、卡片是否能读清。
导出：6 张 PNG、正文标题与话题、来源与音乐建议。示例只是内容结构，正式内容需任务运行时检索。

## 12. 验收与评估
建立 20 个真实任务样本，覆盖资料足够、资料缺失、时间敏感、冲突来源、用户原创照片、局部编辑、生成失败与预算耗尽。先记录基线，再调整提示词。

初版验收目标（工程目标，不是已测成绩）：
- 核心事实证据覆盖率 100%，未验证事实不得伪装为已验证。
- 导出素材出处/授权状态覆盖率 100%；未知状态阻止该素材进入发布包。
- 渲染文字无溢出、页序正确、已锁定版本不被静默覆盖。
- 修改文字无需再次调用图片生成；只重绘受影响页面。
- 失败恢复能复用已完成输出；预算和取消状态可见。
- 人工分别评 1–5 分：信息价值、可操作性、口吻自然、视觉可读、图文一致。
- 同时记录：可发布率、每篇人工编辑分钟数、用户修改/拒绝原因、调用费用、任务总耗时。耗时报告中位数和 P90，不预先保证秒级成稿。

发布后手工回填 24 小时/7 天数据。比较同账号、相近题材与发布时间窗口，记录曝光量和分母；数据小的时候报告观察，不把单篇涨跌当作因果。封面/标题候选最初用于人工选择，不称为平台随机 A/B 实验。

## 13. 实现顺序
预计 3 个迭代，时间取决于开发投入和服务接入：
- 迭代 1：热点样本导入/只读采样适配器、TrendPack、文本结构、3 套排版模板、整组 PNG、逐页编辑、下载。先验证从热门参考到原创作品的闭环。
- 迭代 2：调研工具、证据/素材记录、账号风格、AI 插图、事实与版式质检。
- 迭代 3：持久化任务、局部重试、预算、恢复、人工审核、音乐建议、反馈统计。
第一版暂缓：自动发布、评论互动、全站热榜抓取、短视频合成、模型微调、大型多 Agent 团队。

## 16. 热门信息驱动：用户补充后的核心设计
用户要求：BGM、内容、配图均由 Agent 参考热门信息。本节属于核心需求，覆盖前文中仅给音乐风格建议或将平台观察后置的默认方案。

### 16.1 工作流程
Brief → TrendResearch（近期样本与音乐候选）→ TrendPack（带来源的热点摘要）→ Planner（目标筛选、原创角度）→ Writer / ArtDirector / MusicSelector → 联合质检 → 人审与导出。

同一 TrendPack 同时服务三种生成，不让文案、配图、BGM 分别跟随无关趋势。配图参考热门视觉结构，实际素材仍需原创/有权使用。

### 16.2 如何定义热门
默认优先观察近 7 天，样本不足时扩到近 30 天，保留日期。24 小时只用于突发时效题材。MVP 不是全站热榜，而是“与意图、受众和账号相关的近期高互动样本”。

采样：3–5 个相关关键词；默认去重后 20–30 条摘要，深读 5–8 条；热门、最新及普通样本混合。数量由预算控制，平台访问受限时返回 partial，不假装采样完整。
信号：公开点赞、收藏、评论；发布时间；账号规模（有则记录）；同题材中位数（样本足够才计算）；评论需求；音乐可识别元数据。
只拿到一次互动快照可称“高互动”，不可称“互动增长很快”。增长需要两次可比快照且记录间隔。拿不到阅读量，不计算收藏/阅读；拿不到音乐使用数，不编造使用热度。

### 16.3 三类观察
| 对象 | 分析字段 | 生成约束 |
|---|---|---|
| 内容 | 高频选题、标题承诺、正文/分页结构、评论问题、已饱和角度 | 选择适合目标的结构，并添加新证据、实操或更明确受众 |
| 配图 | 色板、字号层次、字数密度、封面构图、照片/插画/卡片类别、主体、跨页一致性 | 提取抽象视觉规律，生成自己的版式与插图；不得直接搬运封面 |
| BGM | 歌曲/版本/音乐 ID、来源平台、样本出现次数、榜单日期、情绪、节奏、适用题材 | 优先同平台同领域适用候选，输出可核验曲目和版本；平台可用状态需确认 |

视觉趋势必须读取实际图片并用 VLM/程序分析；仅从标题不能声称已分析构图。
BGM 元数据提取失败可结合用户提供的音乐链接/截图；不以歌单标题“热门”替代官方榜单或真实使用证据。需要音频识别时后续增加识别服务，并标记置信度。

### 16.4 TrendPack 数据契约
trend_pack_id、platform、query_terms、time_window、fetched_at、expires_at、
coverage_status（complete/partial/unavailable，complete 仅指计划采样完成，非全站覆盖）、
sample_ids、content_patterns、visual_patterns、music_candidates、audience_questions、saturation_notes。

每个 pattern 包含：
pattern_id、description、supporting_sample_ids、sample_count、confidence、limitations。

music_candidate 包含：
title、artist、version、music_id（可空）、source_platform、source_url、
observed_at、ranking_date（可空）、rank（可空）、observed_sample_count、
mood、tempo（未测则为空）、availability（unknown/verified）、rights_status。
不同平台和版本的同名曲目不自动合并。

计划追加：
selected_trend_ids、chosen_angle、original_contribution、rejected_trends_and_reasons。
每页关联 visual_pattern_ids；音乐选择关联 candidate_id。预览可展开“为何选择这一内容/视觉/音乐”。

### 16.5 排序不是只看流量
先用目标受众/题材/可用来源/账号定位做硬筛，再多维排序。
可用初始启发式：意图匹配 30%、目标匹配 25%、时效 15%、有依据的互动信号 15%、原创空间 15%。权重是产品起始配置，不是已验证流量预测模型。
缺失互动数据时标为未知并调整可用维度权重，不把缺失当作零或编造估计值。
内容热门不代表有事实依据；事实核验独立执行。
音乐的情绪和阅读干扰程度、平台可用性比跨平台热度更优先；避免热门但风格冲突。

### 16.6 接入选择与实测边界
小红书只读采样候选：
- https://github.com/xpzouying/xiaohongshu-mcp
  本次核对 mcp_server.go：search_feeds 支持综合/最新/最多点赞/最多评论/最多收藏，发布时间选项为不限/一天内/一周内/半年内；get_feed_detail 用于详情。30 天观察窗口可对日期做本地后过滤，不能假设有原生“一月内”筛选。
- https://github.com/lucasygu/redbook
  README 支持 popular/latest/general 搜索及内容读取。是否可拿到音乐元数据未确认，不能直接承诺。

首版实现统一 TrendProvider；先验证上述候选的只读搜索/详情/图片字段，发布与互动工具不向 Agent 暴露。不可用时使用用户提供样本或有合法访问条件的数据源，展示数据缺口。

BGM 数据源：
1. 小红书同领域热门样本里可获取的音乐信息（字段可用性待实测）。
2. 用户提供的小红书音乐页/曲库截图，补齐平台候选与版本。
3. 抖音官方音乐热榜/飙升榜作为跨平台灵感，清晰标注平台，不称作小红书热门。
官方音乐飙升榜文档：
https://open.douyin.com/platform/resource/docs/openapi/data-open-service/tops-data/music-list-data/ascending-songs-list/
文档要求申请 data.external.billboard_music 权限，属于离线每日更新数据；不能默认个人项目已经获批。榜单可查询不等于已获得音频下载/发布授权。

若无法取得可核验音乐候选，任务 music 状态为 needs_input，交付风格建议并说明缺口。设计上必须支持热门 BGM，但不能用臆造曲目满足字段。

### 16.7 热点有效期、预算和审核
样本/榜单必须记录抓取时间与数据日期。热门参考默认 24 小时缓存，主题可覆盖配置；导出时若超过有效期，提示刷新热点摘要。无需每次修改文字都重新抓取。
同一来源只读缓存与去重，限制深读/配图次数，避免为了热点产生无限检索。
热点研究页：展示 3 个可选方向、参考样本、视觉规律、3 个可核验 BGM 候选（不够则显示实际数量）、各自来源与缺口。
首版验收新增：
- 每条“热门”判断能回溯平台、时间窗口、样本和实际指标。
- 文案、视觉和 BGM 的采用理由能回溯同一 TrendPack。
- 无榜单/元数据时明确标记未知，不输出假热度。
- 不直接搬运原图，不把样本互动关联解释为音乐/版式带来的因果。
